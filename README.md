# 미끼폰

가짜 휴대폰이나 업무용 PC를 평소처럼 쓰고 끝내면, 내가 **무엇 때문에** 속는 사람인지 유형으로 알려주는 웹 시뮬레이션입니다. 서버와 AI API 없이 규칙기반으로 동작하는 정적 사이트입니다.

> 교육·오락용 자가진단입니다. 실제 보안 수준을 측정하지 않습니다.

## 실행

```bash
python3 -m http.server 8000   # 저장소 루트에서
# 브라우저에서 http://localhost:8000
npm test                      # 점수 로직 + 보안 점검 테스트 (의존성 없음, Node 18+)
```

## 동작 원리

**v2: 폰 쓰는 5분.** 처음 버전은 알림 10개(피싱 8)를 차례로 판단하게 했는데, 결과가 너무 예측 가능했습니다. 사용자가 '함정 테스트'라는 걸 알고 의심 모드로 들어가면, 실제 행동이 아니라 시험 보는 행동을 재게 되기 때문입니다. 그래서 구조를 바꿨습니다.

1. **볼일이 있는 폰:** 홈 메모에 할 일 4개가 있습니다(답장, 배송 확인, 카드값 확인, 도중에 생기는 카드 분실 신고). 사용자는 피싱을 찾으러 오는 게 아니라 볼일을 보러 폰을 씁니다.
2. **진짜와 가짜가 반반, 짝지어 배치:** 피싱 8개와 진짜 연락 8개가 시간표대로 섞여 옵니다. 진짜 배송 알림 뒤에 가짜 택배 문자, 엄마의 진짜 전화 뒤에 '엄마(새 번호)', 카카오톡으로 온 진짜 청첩장 뒤에 모르는 번호의 가짜 청첩장이 옵니다. 링크를 여는 것 자체가 항상 틀린 게 아닙니다.
3. **강제 선택 없음:** 배너는 4.5초 뒤 사라지고 연락은 앱에 쌓입니다. 무시해도 됩니다. 전화는 15초 울리면 부재중이 됩니다.
4. **확인은 실제 앱 행동으로:** "공식 앱에서 확인" 같은 버튼은 없습니다. 쇼핑몰 앱 공지를 열거나, 엄마 원래 번호로 전화하거나, 은행 앱에서 분실 신고를 하면 그 피싱에 대해 '직접 확인함'으로 기록됩니다(피싱이 도착한 뒤의 행동만).

### 점수

- 피싱마다: 안 물면 0점, 링크·통화·답장까지 1점(진입), 설치·정보 제공까지 3점(노출).
- 피싱마다 심리 축(권위·긴급·이득·친밀) 가중치(주축 1.0, 보조축 0.5). 축별 점수 = 받은 점수 / 최대 점수 × 100.
- 진짜 연락마다: 확인함(읽음·답함·받음) / 놓침 / 지우거나 신고함.
- 유형 판정 순서
  1. 위험 지수 15 미만, 노출 0회, 진짜 연락 절반 이상 확인 → 분별형
  2. 위험 지수 15 미만, 노출 0회, 진짜 연락 절반 미만 확인 → 일단 차단형(의심을 잘한 게 아니라 다 거른 것)
  3. 그 외 → 가장 높은 축의 유형. 동점이면 노출이 있는 축, 그다음 권위 > 긴급 > 이득 > 친밀
- 손 속도: 미끼에 반응한 것 중 절반 이상을 '읽기 기준시간(글자 수 × 0.1초)'보다 빨리 했으면 번개손.

**v3: 쓰던 폰 + 대화형 통화.** v2 피드백(아이콘이 가짜 같음, 같은 회사 문자가 같은 방에 오지 않음, 발신번호가 전부 010)을 반영했습니다.

- 문자·토크·메일·통화 기록에 지난 대화를 미리 채웠습니다. 진짜 한빛택배·다온은행 문자는 그 기존 방에 쌓이고, 가짜는 낯선 번호의 새 방으로 옵니다. 실제 폰에서 가장 쓸모 있는 판별 단서입니다.
- 발신번호를 국제발신(+63), 070, 02, 1588, 114, 010으로 섞었습니다. 진짜 택배 기사는 010으로 전화합니다. "010이면 위험" 같은 단순 규칙으로는 풀리지 않습니다.
- 모든 통화(받는 전화, 거는 전화)는 대사를 골라 진행합니다. 연락처에 아빠, 박 팀장, 한빛의원 같은 일반 연락처를 넣었습니다.
- 확인 행동은 전화를 건 것만으로 기록하지 않고, "혹시 새 번호로 카톡 보냈어?"처럼 실제로 물어본 대사에서만 기록합니다.

**v4: PC 모드 추가, 일상 사용 확장.** 최근 보안 바이럴이 PC 쪽에서 많이 나와서 업무용 PC 모드를 추가했습니다. 미끼는 가짜 로봇 확인(명령어 붙여넣기 실행), 압축 파일 속 `.pdf.lnk`, 같은 이름·다른 주소의 거래처 메일, IT팀 사칭 설치 파일, 가짜 감염 경고창, 팀장 사칭 상품권 요청, 보상금 조회 프로그램, 지인 새 계정 링크입니다. 휴대폰 모드에는 카메라·사진·지도·설정(방해 금지 포함)과 점수와 무관한 일상 연락(광고 문자, 단톡방, 텔레마케팅 전화)을 넣었습니다.

## 측정 편향을 줄이려고 한 것

- 진짜 연락을 섞고 짝지어 배치했습니다('전부 의심'이 최고 점수가 되는 것 방지, 분별력 측정).
- 선택 패널 없이 실제 폰 위치에 버튼을 뒀습니다(시험 보는 느낌 제거).
- 어떤 버튼에도 미리 초점을 주지 않고, 위험한 답장이 늘 첫 번째에 오지 않게 했습니다.
- 진행 중에는 정답을 알려주지 않습니다.
- 시간표는 모든 사용자에게 같습니다(결과를 서로 비교할 수 있게). 탭을 벗어난 시간은 세지 않습니다.

## 대화 흐름·결과 화면 개선

- PC 메일과 메신저는 도착한 연락과 주고받은 답장을 하나의 발생 순서로 표시합니다.
- 상대 답장을 기다리는 동안 다음 답장을 잠시 숨기고, 중복 클릭을 막습니다. 새 메일을 받은 뒤 이전 메일의 미완료 답장이 다시 나타나지 않습니다.
- 다시 시작하면 이전 세션에서 예약된 답장은 새 세션에 들어오지 않습니다.
- 결과는 핵심 수치와 실천 팁을 먼저 보여주며, 상세 행동 기록은 펼쳐 볼 수 있습니다. 복사는 ‘결과 복사’ 하나로 통합했습니다.
- 앱 아이콘, PC 편지함·첨부파일·답장 영역과 데스크톱 표면을 다듬었습니다.
- `tests/conversation.test.js`에서 메시지 순서, 답장 대기, 중복 클릭, 세션 분리와 결과 구성을 검증합니다.

## 실제 앱을 참고한 포트폴리오 화면

- 모아몰·토크 등의 가상 소비자 앱 표기를 쿠팡·카카오톡·Chrome·Gmail·토스뱅크 등으로 변경했습니다. 대화·상황은 가상이며 링크는 `.example`로 유지됩니다.
- 한빛상사 과제는 ‘회사 소개서 받기’입니다. 홈페이지의 다운로드는 가짜 보안 확인 시나리오이고, 같은 화면의 ‘담당자에게 메일로 요청’으로 정상 소개서를 받을 수 있습니다. 메일 첨부 소개서를 열면 완료됩니다.
- 휴대폰에 X와 네이버 블로그를 추가했습니다. PC에서는 Chrome 즐겨찾기로 블로그를 엽니다. 피드, 좋아요·팔로우, 글 읽기·공감은 로컬로 동작합니다.
- 사진 10장을 갤러리·PC 이미지 뷰어·채팅·상품·피드에 연결했습니다. 출처는 ASSET_CREDITS.md와 assets/sources.json에 기록했습니다.
- `python scripts/build.py`로 이미지까지 내장한 `dist/preview.html`을 만들 수 있습니다. Windows 맑은 고딕과 Linux Noto CJK 글꼴 경로를 지원합니다.

## UI 및 정합성 재점검

현재 배포 중인 공식 스토어의 카카오톡·토스·블로그 화면을 참고해 구성을 다시 정리하고, 아이콘 8종을 실제 앱 표지로 교체했습니다. 변경 내용·출처·검증 범위는 `UI_AUDIT.md`를 참고하세요.

청첩장 링크 위치, 도착 전 대사, 인증 문자, 체크카드 내역, 견적서 과제 조건을 수정했습니다. 결과는 요약과 기호 없는 상세 펼침 하나로 구성했습니다. 카메라는 샘플 장면을 실제로 잘라 저장하고 갤러리·즐겨찾기와 연결합니다. X와 블로그의 글·사진은 서로 다릅니다.

`css/apps.css`는 가상 휴대폰의 일관된 색상과 앱별 화면을 담당합니다. 이 스타일은 단일 HTML 미리보기에도 내장됩니다.

### 진행 시간·PC 미션 수정

- 폰·PC 상단에서 진행도 바 확인 및 언제든 결과 보기 가능. 모든 연락을 열거나 일정 시간을 채울 필요 없음
- 예약 알림의 원래 순서를 유지하며 PC 예약 알림은 최소 8초, 3분 폰 모드의 주요 피싱은 최소 16초 간격 적용. 답장 지연은 유지하고 카드 분실은 중반에 배치
- 회사 소개서 받기는 저장 또는 열기로 완료. 견적서는 내용 확인 후 거래처 회신 시 완료
- 시작·결과 안내를 짧은 문구로 변경하고 기기 바깥 배경은 차콜 단색(#303030)으로 통일


### 갤럭시 내비게이션·일상 맥락 시나리오

- 모바일 소개 화면에 22px 이상 좌우 여백과 유동 너비 적용
- One UI 스타일의 최근 앱·홈·뒤로 3버튼과 동작하는 최근 앱 목록 제공
- 휴대폰: 배송 → 가족 통화 → 모임 답장 → 모르는 결제·카드 분실 → 청첩장 → 지수 답장 순으로 일상 맥락을 만들고 관련 피싱을 사이에 배치. 분실 미션은 66초, 지수 연락은 93초
- 폰 미션 6개, PC 미션 5개. PC 업데이트 미션은 실제 공지 확인과 예약이 모두 필요
- PC 감염 팝업은 후반에 브라우저를 사용 중인 경우에만 등장
- 흐름과 심리적 맥락에 대한 설계 가설은 SCENARIO_FLOW.md 참고


### 시간·메모·홈 화면 보정

- 시작 버튼은 폰 3분, PC 3분을 모두 표시
- PC 마지막 예약 이벤트 163초, 폰 마지막 예약 이벤트 146초. 전체 세션을 250ms 단위로 진행하는 테스트에서 모든 예약 이벤트 도착과 자동 종료 확인
- 메모는 첫 항목만 보이고 이후 15초 간격으로 공개. 연락과 연결된 미션은 해당 연락 도착 이후 공개하며 연락 대기 표시는 없음
- 하단 탐색 버튼은 아이콘만 표시하고 접근성 이름은 유지
- 홈 앱 목록은 5열·2행으로 배치하고 짧은 화면에서는 메모·아이콘 크기를 조정


### 이벤트 정합성 점검

폰과 PC의 이벤트·분기·미션 점검 결과는 [EVENT_AUDIT.md](EVENT_AUDIT.md)에 정리했다. 모바일 브라우저에서는 터치·모바일 기기 신호를 함께 확인해 세로일 때 PC 시작을 막는다. 휴대폰 홈은 최종 메모 높이를 처음부터 확보해 앱 위치가 고정된다.


### 전체 화면과 종료 방식

- 폰·PC 모두 플레이 권장 시간은 약 5분. 자동 종료 시각은 없고 언제든 결과를 열 수 있음
- 예약 이벤트가 모두 도착하면 진행 바가 완료되고 상단에 ‘이벤트 종료’와 ‘결과 확인’ 표시
- 전체 화면 버튼은 브라우저가 지원하는 경우 주소창·탭을 가리는 전체 화면을 요청. 미지원 iPhone Safari는 공유 → 홈 화면에 추가 → 웹 앱으로 열기 안내
- 플레이 중 브라우저 뒤로가기는 게임 화면 이동으로 처리. 게임 홈에서 누르면 계속하기/처음 화면으로 선택. 종료 후 브라우저 뒤로가기는 원래대로 동작


### 최근 앱과 파일 미리보기

- 폰 최근 앱은 마지막 앱 화면을 카드로 표시. 좌우로 넘기고, 카드를 누르면 재진입, 위로 밀면 개별 닫기, ‘모두 닫기’로 홈 복귀
- 최근 앱 아이콘은 기본 앱과 브랜드 앱 모두 동일한 26px 영역에 표시. [삼성 최근 앱 안내](https://www.samsung.com/us/support/answer/ANS10001359/) 참고
- PC 문서·사진 미리보기는 창 바깥을 클릭하면 닫힘. 미리보기 내부 클릭과 실행 승인 창의 동작은 유지
